# LG Aimers 9th — Pitch Control Prediction

LG Aimers 9기 Phase 2 야구 투구 단위 제구 성공 확률 예측 프로젝트입니다.

## 기록

- 검증된 최고 리더보드 BSS: **1051.5537225994**
- 현재 최고 구성: 5멤버 블렌드(hgb·cat·nn·team·team_nn) + **시즌 상태 복원 피처** + 잔차 보정 3종(좌우·카운트·카운트유불리) + 콜드스타트 전문가
- 이전 최고 BSS: **1031.921685975** → **1016.4442212358**
- 모델: calibrated GBDT blend + player embedding MLP
- 판정 도구: 롤링 3폴드 백테스트 + 2σ 노이즈 바닥 + 행 독립성 자동 테스트
- **이어서 작업하려면 [`docs/HANDOFF.md`](docs/HANDOFF.md) 를 먼저 읽으세요** — 현재 위치·판정 규칙·다음 할 일·기각 기록이 전부 거기 있습니다.

## 15~18차에서 한 것

### 판정 방법을 먼저 바꿨다

14차까지 14번 중 5번이 "로컬 개선 → 리더보드 하락"이었다. 단일 2024 홀드아웃은 시즌
전이를 한 번만 보므로 우연에 취약하다. 시즌 전이를 세 번 재현하고 **폴드별로** 판정한다.

- `src/backtest.py` — 롤링 3폴드 (~21→22, ~22→23, ~23→24). 피처 빌더가 `train_seasons`
  를 인자로 받아 미래 참조가 구조적으로 불가능하다.
- **2σ 노이즈 바닥** — 예측 차이 δ 만으로 `2·100000·√(Σδ²)/(n·0.2498)`. 정답 라벨이
  필요 없어 제출 전에 유의성을 판정할 수 있다.
- **재학습이 끼면 노이즈 바닥이 다르다** — 같은 피처로 시드만 바꿔도 폴드별 ±27 이
  흔들린다. 피처·하이퍼파라미터 비교는 반드시 양 팔을 다중 시드로 돌린다.
- **폴드 평균을 믿지 않는다** — 2023 폴드는 F 구간 레짐 붕괴(.709→.473)로 극단값을 내
  평균을 통째로 끌고 간다.

검증: 7차 제출의 실제 실패(count×hand, LB −11.8)를 이 백테스트가 재현했다.

### 15차 — 잔차 보정 3종 (+15.48)

정보원별 천장을 재보니 신호가 거의 전부 투수 정체성이었다 (2024 R: `pitcher_id` 683.5,
현재 모델 737, `pitcher×좌우` **783.9**). 상황 변수는 7~23 에 불과했다.

| 보정 | 조회 키 | k |
| --- | --- | --- |
| β 투수별 좌우 스플릿 | `(pitcher_id, batter_hand)` | 2000 |
| γ 카운트 | `balls*3+strikes` | 5000 |
| δ 투수별 카운트 유불리 | `(pitcher_id, 유리/중립/불리)` | 2000 |

설계 규칙 넷을 지켜야 부호가 뒤집히지 않는다: ① 잔차는 out-of-sample ② 풀링 전
시즌별 중심화 ③ 투수 상호작용은 주효과를 뺀 순수 편차 ④ R 행에서만.

### 18차 — 시즌 상태 복원 피처 (+19.6)

`season_form` 은 `asof_pitcher_success_rate` **하나**를 시즌 단위로 복원해 +37.7 을
얻었다. 그런데 같은 산술이 **10개 `asof_*` 컬럼 전부**에 성립한다 — `rate × n` 이
정확히 정수 카운트이고, 시즌 경계 누적값을 train 상수로 얼리면 각 행이 자기 값만으로
당해 시즌 상태를 복원한다.

    n_season = asof_n − n0
    cur_X    = (round(asof_n × rate_X) − c0_X) / n_season

그리고 중복이 아니다: `success + (middle+ball+reverse)` 평균이 1.2738 로 분할이 아니고,
`strike_rate` 는 성공률과 상관 +0.15 로 거의 직교하다. middle/ball/reverse 는 문제
정의의 실패 3유형과 1:1 대응한다.

복원 정확도: 복원한 2024 시즌 성공률 vs 실제 2024 성적 상관 **0.9998** (커리어 누적은
0.6879). `season_form`/`batter_form` 은 이중 계산이 되므로 끈다.

### 17차의 실패에서 배운 것

수준 보정을 두 번 적용해 899.15 (−132.8) 를 받았다. 원인은 **검증 도구**였다. 그때까지
리허설은 "2024 행의 `season` 만 2025 로 바꾼" 합성이라 `asof_n < n0(2024말)` 이 되어
시즌 상태 피처가 전부 결측이었고, 그래서 수준을 검증할 수 없었다.

`scripts/make_proxy_2025.py` 는 `asof` 값 자체를 옮겨 "2024 시즌 상태"를 "2025 시즌
상태"로 이식한다(결측률 0.199 로 실제와 일치). 수준에 영향을 주는 변경은 예외 없이
이걸로 먼저 확인한다.

일반형: **시즌 상태 피처가 있으면 모델이 기저율 드리프트를 스스로 흡수한다.** 그 위에
드리프트 보정을 또 얹으면 과보정이 된다.

### 기각 기록 (재시도 방지)

Trackman 물리 피처(잔차 상관 ≤0.016) · Trackman 카운트별 구종 구성(칸 내부 상관
+0.0082) · R-only 캘리브레이션(~0) · season-form 재튜닝
(2024 폴드 +2.8) · L2 목적함수 · CatBoost 멤버 · 시즌 감쇠 학습가중(−14.1) ·
asof 오프셋(−36.6) · F 학습 제외(−25.9) · 구종 엔트로피(−9.4) · 다중 창 피처(−9.4) ·
블렌드 비중 재최적화(LOFO +0.6) · ID 비중 상향(LOFO −1.5) · 콜드스타트 비중(LOFO −0.5)

살아남은 셋은 전부 **"이 투수가 상황에 따라 어떻게 달라지는가"** 축이었다. 구장·주자·
이닝·홈원정·포수·레버리지 등 상황 자체는 전부 0 이었다.

## 파일 역할

`submission/`은 제출 ZIP의 압축을 풀었을 때 보이는 구조입니다. 개발 중에는 이 폴더의 코드와 모델을 수정합니다.

`dist/submit.zip`은 업로드용 빌드 결과입니다. Git에 커밋하지 않고 필요할 때 생성합니다.

`artifacts/submit_40pct_lb939.918632.zip`은 실제 리더보드에서 939.9186320496점을 기록한 보존용 스냅샷입니다. `submit_optimal_39.094pct_expected939.919868.zip`은 네 번의 실제 제출 점수로 복원한 최적 혼합비 후보이고, `submit_nn10_candidate.zip`은 **957.6295435994점**을 기록했습니다. 현재 최고 제출물은 `submit_season_state.zip`이며 실제 리더보드 점수는 **1051.5537225994**입니다.

## 학습

대회 데이터를 저장소 루트의 `data/`에 배치한 뒤 실행합니다.

```bash
python -m src.train_base
python -m src.train_monotone
```

첫 번째 명령은 기본 모델 3종을 학습하고, 두 번째 명령은 단조 제약 모델을 학습한 뒤 60.9056:39.0944 앙상블 메타데이터를 구성합니다.

## 제출 ZIP 생성

```bash
python scripts/build_submission.py
```

생성 결과:

```text
dist/submit.zip
├── model/

```

## 모델 구성

- 일반 LightGBM GBDT (`num_leaves=31`, `63`)
- 최근 시즌에 높은 표본 가중치를 적용한 LightGBM
- 제구 성공·스트라이크 비율에 양의 단조 제약 적용
- 가운데·반대·볼 비율에 음의 단조 제약 적용
- 각 앙상블에 고정 확률 캘리브레이션 적용
- 수치형 중앙값 대치·표준화와 결측 플래그를 적용한 MLP
- 투수·타자 ID 임베딩 및 신규 선수 대응 ID dropout 적용

현재 최고 제출은 R10 이종 앙상블 복원본을 기반으로 합니다. 마지막 단계에서 기존 투수 season-form(`M=75`, `alpha=0.28`)과 타자 season-form(`M=50`, `alpha=0.11250648296393913`)을 적용합니다. 이어서 train 기간에 정규시즌 기록이 없는 투수의 `game_type=R` 행에만 투수·타자 ID를 입력에서 제외한 LightGBM 예측을 `41.81944104%` 혼합합니다. 모든 분기와 보정은 각 평가 행의 값과 train-only 고정 모델·상수표만 사용하는 행 독립 방식입니다.

## 규정 준수

추론은 각 테스트 행의 값과 학습 시 고정된 모델·매핑만 사용합니다. 테스트 데이터의 다른 행을 이용한 집계, rolling, lag, 빈도, 순위 또는 분포 보정은 사용하지 않습니다.

대회 데이터는 배포 규정에 따라 저장소에 포함하지 않습니다.
